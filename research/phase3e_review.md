# 阶段 3 正式结果复核与下一轮设计（给 Codex）

> 依据：`MCZhouyf/VLA` main 提交 `5e7a804`。编写日期 2026-11-25。
> 本文件取代 `phase3d_review.md` 中尚未执行的部分。

## 1. 结论

1. **按原定标准，这一轮没有通过**：30 格档无记忆 0/30、空间记忆 0/30，两组都在原地左转（96–98% 的步数）。
2. **失败原因已经定位，不是“记忆没用”，而是“记忆没被用上”**：
   - 控制器学到的是“向左转着找目标”。目标被遮住后它只会一直转，跟有没有记忆无关。
   - 打乱、清零、旋转记忆或去掉记忆前缀，贪心动作都不变，说明模型**完全忽略了记忆 token**。只用动作损失训练时，标签 90% 是前进，模型不需要记忆就能把损失降得很低，所以它学会了不看记忆。原方案里的辅助损失（“目标在哪个方向、多远”）在阶段 3 被推迟了，这正是缺的那一环。
3. **布景还有一个泄漏**：出生点离金柱只有 2.83 格，“回到第一个位姿”或“沿路折返”不需要认出金柱也能成功。所以 RGB 检索 + 折返的 14/14 不能算作视觉记忆的证据。
4. 正面信号：用真值位姿“沿历史路线折返”在 30 和 100 格都是 30/30，RGB 检索 + 折返在打乱图像和位姿对应后从 14/14 掉到 3/14。说明“记住走过的路 + 认出目标在哪”这条路是通的，问题在于把它接进模型的方式。

## 2. 下一轮：分层设计——记忆负责“去哪”，控制器负责“怎么走”

把一个模型同时学“记住目标在哪”和“怎么走过去”拆成两部分，每部分都有直接监督，并且可以单独测上限。

### 2.1 任务修正（T1 v3，先做，CPU）

1. **出生点和起始观察点离金柱至少 8 格**：智能体在外出段开头从远处看到金柱，而不是站在旁边。
2. **两个候选位置交换**：外出路线经过两个外观相同的围挡，一个里面是金柱，另一个是非金色干扰柱。哪个是金柱按种子随机（各 50%）。
3. **判定改为“先到者为准”**：先进入干扰柱 3 格半径即判失败。这样“沿路折返”只能拿到约 50%，必须**记住哪个围挡里是金柱**才能超过它。
4. 验收：教师 ≥ 95%；转 180 度、扫视、找结构、**沿路折返（真值位姿）**、**回到起点**五个脚本基线在 30 格及以上都要报告。沿路折返应接近 50%，其余 < 10%。
5. 重新采集数据：四档 + 可见导航，规模同上一轮。种子与已有划分、冻结评测都不重叠。

### 2.2 控制器：航点条件导航（阶段 A）

1. 用已通过近距门槛的共享 LoRA 作为起点，在提示里加入**航点**：以自身为中心的方向和距离，文本形式如 `waypoint: left 30 deg, 12 blocks`（方向 8 档 + 距离 3 档，或 10 度、1 格分辨率，二选一并固定）。
2. 训练数据：教师回程中，每步的航点由真值位姿计算，取教师路线上前方 5–8 格的点。加入第 3 节的扰动数据（DART），并以 0.5 概率丢弃历史动作文本，防止抄袭。
3. **验收（预言机航点）**：给控制器真值航点，T1 v3 四档成功率 ≥ 80%。这是整篇论文的上限，也证明控制器不再原地打转。不到 80% 先修控制器，不进入阶段 B。

### 2.3 记忆模块：预测航点（阶段 B）

1. 冻结控制器。空间记忆模块（32×32×8 网格，真值位姿写入，32 个查询）输出航点，用教师航点做交叉熵（方向）+ 回归 / 分类（距离）监督。另加一个辅助头：预测**金柱相对当前位姿的方向和距离**（原方案的 “where is X”）。
2. 对照组，输出头和损失完全相同，只换输入：
   - ① 无记忆：只看当前帧和 2 帧历史；
   - ② 长窗口：8 帧历史；
   - ③ 空间记忆；
   - ④ 真值航点（上限）；
   - ⑤ 沿路折返（真值位姿脚本，约 50%）。
3. **离线检查**（先做，几小时）：在验证集上报告航点方向准确率和“金柱方向”准确率，按“两个候选中选对了哪个”分组。空间记忆组必须明显高于无记忆组（例如方向准确率高 20 个百分点以上），否则先查记忆读出，不进闭环。
4. **记忆使用检查**：对空间记忆组重复上一轮的四个探针（打乱视觉、清零、旋转位姿、去掉前缀），这次航点预测**必须**发生变化。

## 3. 新的继续 / 止损标准（30 格档，T1 v3，30 个冻结种子）

| 组 | 要求 |
| --- | --- |
| ④ 真值航点 | ≥ 80% |
| ① 无记忆 | ≤ 60%（略高于 50% 的猜测水平） |
| ③ 空间记忆 | ≥ 75%，且比 ① 至少高 20 个百分点 |

三条都满足就继续扩展到 60/100 格和长窗口。④ 过、③ 不过，说明是记忆读出的问题；④ 不过，说明是控制器的问题。

## 4. 顺序与时间

| 步骤 | 资源 | 预计 |
| --- | --- | --- |
| T1 v3 布景 + 五个脚本基线 + 重采集 | CPU | 1 天 |
| 控制器航点训练（从共享 LoRA 续训） | GPU 6 | 约 6–8 小时 |
| 记忆模块训练（冻结 LoRA，只训小模块，可缓存视觉特征） | GPU 7，三组可并行 | 每组数小时 |
| 预言机航点验收 → 三组离线检查 → 30 格闭环 | 两卡 | 1 天 |

**这一轮是最后一次在当前设计上的尝试**：如果④达标而③仍不比①高 20 个百分点，就停下来汇报，转为备选方案（把 MineMem 做成“VLA 不会用记忆”的基准与分析论文）。
