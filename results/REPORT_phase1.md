# MineMem 阶段 1 验收报告

**阶段 0 通过，阶段 1 的 T1 教师验收通过，JARVIS-VLA 基线门槛未通过。** 两项公开 MCU 任务和 5 格导航各完成 10 个种子。炼制铁锭在论文数值容差内，合成工作台和导航均未达标。5 种子模型试点和 30 种子正式悬崖图依原验收条件保持阻塞。阶段 0 的原始数据以 GitHub 提交 `149623bf` 为准。[阶段 0 固定归档](https://github.com/MCZhouyf/VLA/tree/149623bf2bd9fcad4a79e919831b8f9aed3abfa8)

## 1. 阶段 0 动作复核

从两份 `steps.csv` 逐行取阶段 0 实际执行的第一个带界符动作，使用固定版本的 `OneActionTokenizer` 和 MineStudio 的相机映射解码。按钮比例按各自总控制步数计算。Pitch 和 yaw 均使用 21 档，中位空动作是 10。[全部按键和分箱 CSV](phase1_jarvis_phase0_actions.csv)

| 按键或相机分箱 | 自然森林 500 步 | 受控挖石 16 步 |
| --- | ---: | ---: |
| `forward` | 1（0.20%） | 0 |
| `attack` | 419（83.80%） | 16（100%） |
| `back`、`left`、`right`、`jump`、`sprint`、`sneak`、`use` 与其余按键 | 各 0 | 各 0 |
| Pitch 10、yaw 10 | 436（87.20%） | 16（100%） |
| Pitch 10、yaw 9 | 64（12.80%） | 0 |
| 其他相机组合 | 0 | 0 |

自然试次唯一的 `forward` 出现在第 118 步。该步水平位移约 0.098 格，后续惯性使首末位移约为 0.210 格。第 119 步的 yaw 分箱 9 对应实测 yaw 变化约 −0.178°，与当前 μ-law 反量化一致。记录表明，这两类生成动作在环境中产生了预期方向的控制效果。自然试次的有限位移主要对应低前进比例，需用官方生成配置检验其任务执行能力。[自然试次逐步数据](https://github.com/MCZhouyf/VLA/blob/149623bf2bd9fcad4a79e919831b8f9aed3abfa8/results/phase0-mcu-JjgkiRLZ/steps.csv)

10 个导航种子均跑满 200 步。**1.5 格口径为 0/10，3 格口径为 2/10**。最小距离的中位数为 3.80 格，表现最接近的回合到达 2.52 格。逐步解码显示 2,000 步中有 93 步前进、1,807 步攻击和 0 步跳跃。模型在多次试验中产生了有效走动，距目标的多数门槛未通过。[导航逐回合结果](phase1_jarvis_navigation.csv) · [原始逐步数据](phase1-jarvis-gate-FcFOx50o)

## 4. T1 教师

四档设为 10、30、60、100 格，每档 50 个场景种子。每个 CPU 工作进程复用一个固定世界，条件命令查验布景。教师面向金柱停留 40 步，按 1–3 个拐点的路径走到距离档位，末 20 步背对金柱。距金柱至少 15 格布置 2–3 个异材质干扰柱，30 格及以上在目标与外出终点之间布置矮墙。返回时由位姿计算水平最小距离，以 ≤3 格判定成功。较短的成功教师参考回程确定每个场景预算 `2 × 教师步数 + 200`。带墙场景比较两条绕墙参考路线。

初版教师先验证实机走向和重置。第二版记录到 Minecraft 拒绝科学计数法表示的近零 yaw，部分 100 格种子还在途径长距离障碍时停滞。第三版的传送使用定点格式，并把平整草地抬高到原出生面上方 12 格，分条自上而下清除头顶空间。验收使用第三版的同一组世界和场景种子。

## 5. T1 悬崖图与吞吐

运行器已接入随机策略、文本条件 STEVE-1、JARVIS-VLA-7B 与无指令 VPT-BC。四档均有有效教师参考步数的种子已冻结，前 5 个用于试点，其后 30 个用于正式评测。所有模型共享各回合的教师外出段。外出时由脚本控制并记录轨迹，JARVIS-VLA 在返回时接收官方窗口长度的最近两帧和对应动作。正式输出包含逐回合距离、步数、世界与场景种子、回程预算、成功率和 Wilson 95% 置信区间，VPT 结果单列附表。ROCKET-2 作为另有掩码输入的附加实验。[冻结种子](phase1_t1_seeds.json)

在同一实机 T1 场景对随机策略、文本条件 STEVE-1 和 VPT-BC 分别执行了 20 步接口检查。三者都完成了动作生成、同一返回位姿还原和逐步距离统计。STEVE-1 另固定了 MineCLIP 使用的 CLIP tokenizer 修订。接口检查采用缩短步数，仅用于验证运行器。[实机接口检查](phase1-t1-policy-probe-qgLvUhoo/probe.csv) · [策略权重来源](phase1_vpt_bc_download.csv)

正式运行器会检查 JARVIS-VLA 门槛的原始回合、200 份教师验收及冻结名单，随后才加载评测策略。当前缺少可放行的 JARVIS-VLA 结果，因此尚无各基线在四个距离档的正式成功率，`d ≥ 30` 的 20% 规则待正式数据检验。

已在 BAAI 用实际的 30 个阻塞检查回合验证正式运行器会在加载模型前退出。报表的完整性检查和 Wilson 误差线已用覆盖 0% 和 100% 的合成数据验证。[门槛拦截日志](phase1_formal_gate_check.log)

32 个 CPU 工作进程用于教师验收和后续轨迹采集。世界初始化后各实例复用模拟器运行多回合。按教师参考步数，四档每种子的平均返回预算合计 2,722.12 步。按每进程 1.1 FPS 和 4 个进程估算，5 种子约 52 分钟，30 种子约 5.16 小时，均为所有回合跑满预算的纯控制时间。GPU 服务启动、外出段、布景及重置时间另计。

按阶段 0 的 32 实例吞吐 459.87 FPS 外推，采集 5–10 万帧的纯步进时间约 1.8–3.6 分钟，360–720 万帧约 2.17–4.35 小时。实际采集时间还需计入布景、重置及写盘。本轮使用 32 实例档。[阶段 0 吞吐总表](https://github.com/MCZhouyf/VLA/blob/149623bf2bd9fcad4a79e919831b8f9aed3abfa8/results/phase0-capacity-KDJd1VgQ/throughput.csv)

## 6. 双卡四实例容量实测

GPU 6 和 GPU 7 各同时加载两个独立的 BF16 JARVIS-VLA-7B 服务。每实例 vLLM 显存预算为卡容量的 47%，上下文上限 3,072 token，允许每次请求三张图像。四个端口均通过健康检查和模型查询，四路客户端同时起步，每路完成 10 次经过官方封装的多模态推理。

| GPU | 独立 7B 实例 | 就绪显存（MiB） | 请求结束时显存（MiB） |
| ---: | ---: | ---: | ---: |
| 6 | 2 | 37,814 / 40,960 | 38,526 / 40,960 |
| 7 | 2 | 37,814 / 40,960 | 38,666 / 40,960 |

每个实例处理 **1.01–1.04 请求/秒**，四路共 40 次，按最长并发请求窗口折合约 **4.04 请求/秒**。该测量使用内存中的 640×360 RGB 测试帧，计入客户端构造输入、模型推理与动作解码。T1 端到端 FPS 还包含模拟器步进，需由通过门槛后的正式运行实测。[并发请求明细](phase1-gpu-pair-gCqASlXs/probe.csv) · [GPU 就绪快照](phase1-gpu-pair-gCqASlXs/gpu_ready.csv) · [请求结束快照](phase1-gpu-pair-gCqASlXs/gpu_after_probe.csv)

探测完成后停止本轮的四个服务。复查时 GPU 6 与 GPU 7 均为 **0 MiB、0% 利用率**。[释放记录](phase1-gpu-pair-gCqASlXs/gpu_released.csv)

## 7. 阶段结论

T1 教师、布景、位姿判定、种子冻结、三种轻量策略接口与四个 7B 实例的容量检查均已验收。正式 T1 仍依赖可通过导航检查的 JARVIS-VLA 基线；要解释论文合成工作台数值的差距，还需取得论文对应的任务微调权重和评测配置。监督子智能体独立复算了 30 个门槛回合、200 个教师回合及冻结种子。
