# MineMem 阶段 3 遮挡建筑 CPU 审计

审计对象为第二版遮挡布景的 30、60、100 格正式冻结场景，每档 30 个。12 路 CPU 实机实验完成了 90 组配对测量。纯 RGB 找结构策略的三档成功率保守上界分别为 **0%、0%、3.33%**，均低于 10%。原扫视脚本在这三档也均为 0/30。找结构策略使用原冻结回程预算。[结构审计汇总](phase3-speed-xOn8Q5je/structure-audit.json) · [第二版验收记录](t1-review-A8vp1K1p/screened_acceptance_scores.csv) · [冻结种子](phase1_t1_seeds.json)

## 配对可见性与找结构策略

- 分别测量外出终点附近四面墙和金柱外围带入口的遮挡建筑。每回合从存档回程起点旋转 36 个朝向，以有建筑和仅移除当前建筑组的两幅同位姿图像作对照。建筑投影区域内至少 12 个连续灰度材质像素且通道差超过 24 才计可见。逐朝向 CSV 留存偏航和像素数。
- 从同一回程起点复演已记录的教师路线，根据逐步实际位姿得到首次候选建筑画面。通过同位姿移除建筑的配对渲染确认首见，将首次步数、水平距金柱距离和像素量写入 CSV。只有实际确认的建筑画面参与首见统计。
- CPU 对照先扫 36 次，朝最大灰度材质连通区域移动，近墙后尝试辨识开口并沿立面侧移绕行。见到金色即靠近金色区域。控制回调接收 RGB 帧及自身已发出的相机与走位动作。位姿、布景坐标和安装预算由评测器用于配对统计、判定与终止。移动、转向、绕墙都消耗回程预算。
- 每档完成 30 个配对测量后，用真实外出起点的成功数加上未知数作为保守的成功数上界。三档的上界均须小于 3/30。缺控制或使用计划终点的回合计为未知，计划位姿下的控制结果另列。真实起点回合中的死亡和位姿跳变依照冻结协议按失败记。100 格种子 `2026112126` 的教师外出失败，使用 `planned_after_outbound_failure` 起点的控制结果归入诊断。教师首见单独汇总成功复演的真实外出起点回合，只统计配对确认的首见。

本地验证覆盖了全部 90 份布景的原始路径和 world seed、投影和遮挡差分的合成输入、开口检测、纯 RGB 控制动作和不完整门槛检查。冒烟与正式运行使用独立结果目录。[CPU 可见性和找结构实现](../code/minemem/t1_structure_audit.py) · [既有可见性入口](../code/minemem/t1_shortcut_audit.py)

## 100 格死亡与位姿跳变

上一轮转身直走 3 次、扫视策略 3 次，以及本轮找结构 3 次，均为出界后的溺水死亡。Minecraft 服务端的死亡原文为 `MineRLAgent0 drowned`。9 条服务端记录均按工作进程目录和时间与对应 gzip 逐步轨迹配对，日志时间与轨迹写入的差在 0–1 秒以内。重复的同一事件日志行合并为一次死亡。[服务端原文、时间与行号](t1-review-A8vp1K1p/structure_death_cause_evidence.csv)

六条逐步轨迹均在死亡前离开 221×221 的平台范围，跨出平台 5–11 步后降到台面以下。死亡前一步相对台面低 17.00–39.53 格，距离最近遮挡结构的水平包围盒 17.13–74.42 格。死亡时计数增加 1，位置跳到已配置的远端复活台，生命值回到 20。转身直走的 3 个回合开始时也记录到短暂的高度偏移，随后在台面恢复。入口和地面调整的触发条件是发生在建筑附近的窒息或卡墙，这六次均未触发该条件。[六条死亡取证](t1-review-A8vp1K1p/structure_death_forensics.csv) · [取证脚本](../code/minemem/t1_structure_deaths.py)

## 命令和可审计产物

从已分配的 BAAI 项目目录执行。让已运行的训练保持原调度。按已有 CPU 运行规则配置隔离的模拟器数据库后，先用 30 格种子 `2026112105` 实机冒烟。

```bash
export WORK=/share/project/zhoubowen/zhy/zyf MINEMEM_PROXY=
cd "$WORK"
review="$WORK/results/t1-review-A8vp1K1p"
seeds="$WORK/results/phase1_t1_seeds.json"
scores="$review/screened_acceptance_scores.csv"
smoke="$(mktemp -d "$review/structure-smoke-XXXXXXXX")"
bash code/minemem/t1_cpu.sh visibility "$smoke" 1 \
  --structure-scores "$scores" --seeds-file "$seeds" \
  --distances 30 --seed 2026112105
```

完整对照每个工作进程按世界复用实例。每个回合输出冻结配置、36 朝向建筑像素表、教师首见配对记录、逐步 RGB 对照位姿和总表。汇总校验完整冻结覆盖，重复 seed 或 world seed 不匹配会报错。

```bash
full="$(mktemp -d "$review/structure-formal-XXXXXXXX")"
bash code/minemem/t1_cpu.sh visibility "$full" 12 \
  --structure-scores "$scores" --seeds-file "$seeds" \
  --distances 30 60 100
"$WORK/envs/mcvla/bin/python" -B code/minemem/t1_structure_audit.py \
  "$full/summary.json" --seeds-file "$seeds" --inputs "$full"/worker-*/structure.csv
```

如果较远任一档累计 3 次成功，无论剩余回合结果如何都无法通过原门槛。若正式控制未达验收阈值，优先在终点附近加入 2–3 个同形同材质、内部无金柱、距真建筑至少 20 格的诱饵，再以原预算重跑教师、转身直走、扫视和找结构。诱饵后的找结构成功率超过 20% 才测试 `1.5 × 教师回程步数 + 100`。

独立重读归档死亡记录的命令如下。输出使用新文件名，可与本报告的六条取证对比。

```bash
python3 -B code/minemem/t1_structure_deaths.py \
  results/t1-review-A8vp1K1p/screened_acceptance_scores.csv \
  results/t1-review-A8vp1K1p/structure_death_forensics_recheck.csv
```
